# 成长闭环：需求

## 范围

在现有本地任务、星星和历史打卡的基础上，补充休息日、每周回顾和家长确认的奖励兑换。功能保持本地优先；本轮不假定服务端已有对应接口。

## 用户故事

1. 作为家长，我可以把今天标为休息日，并可随时恢复当天任务，避免生病或出行破坏连续记录。
2. 作为孩子，我可以看懂这一周做得怎么样，并知道休息日不会被视为失败。
3. 作为孩子，我可以用已经获得的星星申请一个真实奖励。
4. 作为家长，我可以配置奖励，并确认或拒绝孩子的申请。

## 验收标准

1. 当家长将当天设为休息日时，系统应禁止当天任务继续获得星星，并在任务页清楚说明当天无需打卡。
2. 当历史计算连续完成或周完成率时，系统应排除休息日；休息日不得中断此前连续记录。
3. 当用户打开“我的”页时，系统应展示最近七天的完成率、已完成任务数、休息天数及与前七天的变化。
4. 当孩子申请兑换且可用星星充足时，系统应创建待确认申请并暂存相应星星；星星不足时不得创建申请。
5. 当家长确认申请时，系统应将申请标为已确认；当家长拒绝申请时，系统应退回被暂存的星星并保留申请记录。
6. 当家长新增奖励时，系统应校验奖励名称和正整数星星价格，并使其立即出现在孩子的奖励小铺。

## 非目标

- 不发放现金、支付或第三方礼品卡。
- 不新增儿童社交、排行榜或公开分享。
- 不在没有服务端协议的情况下伪造云同步成功。
